# ISM Digital Museum — 5–7 минутын demo

**Зорилтот хугацаа: 6 минут 30 секунд.** Доорх хугацаанд ярих болон дэлгэц дээр үйлдэл хийх хугацаа хоёулаа багтана. Шууд demo хийхээс өмнө оюутны болон админы account-аа хоёр тусдаа browser profile-д бэлдэж, жижиг JPG/PNG зураг сонгоно. Нууц үг, түлхүүрийг дэлгэцээр харуулахгүй.

## 0:00–0:45 · Зорилго ба технологи

**Дэлгэц:** [Нүүр хуудас](https://swe-hw-9f89.vercel.app/).

**Ярих:**

«Миний хөгжүүлсэн ISM Digital Museum нь Мэдээллийн системийн менежментийн тэнхимийн түүх, багш нар, арга хэмжээ, оюутны бүтээлийг нэг дор хадгалж танилцуулах веб апп юм. Хэрэглэгч зөвхөн мэдээлэл уншихаас гадна өөрийн бүтээлийг нэмэх, зураг оруулах, ирээдүйн оюутанд захиа үлдээх боломжтой.

Frontend-ийг React болон JavaScript, хөгжүүлэлт ба build-ийг Vite, backend-ийг Supabase ашиглан хийсэн. Supabase нь бүртгэл, PostgreSQL өгөгдөл, зураг хадгалах Storage болон хэрэглэгчийн эрхийн RLS хамгаалалтыг хариуцна. Сайт Vercel дээр байрласан.»

## 0:45–1:45 · Үзмэр, хайлт, дэлгэрэнгүй

**Үйлдэл:** Үзэсгэлэн рүү орно → `2026` гэж хайна → хайлтыг цэвэрлэнэ → `Дипломын ажил` төрлийг сонгоно → нэг бүтээл нээнэ → эх сурвалжийг заана. Илэрцгүй үг оруулж мэдэгдлийг харуулаад хайлтыг цэвэрлэнэ.

**Ярих:**

«Үзмэрийн карт бүрд бүтээлийн нэр, зохиогч, он, төрөл, тайлбар харагдана. Дэлгэрэнгүй цонхонд багийн гишүүд, ашигласан технологи, онцлох үр дүн болон байгаа эх сурвалжийн холбоосыг харуулдаг. Холбоос нь байгаа бүтээлд demo, GitHub URL мөн үзүүлэх боломжтой.

Хайлтыг нэр, он, ангилал, технологи зэрэг мэдээллээр хийж, төрлөөр шүүж болно. Жишээлбэл 2026 оны бүтээл эсвэл дипломын ажлыг тусад нь харж байна. Хайлт үр дүнгүй үед хоосон дэлгэц үлдээхгүй, өөр түлхүүр үг эсвэл ангилал сонгох тайлбар өгнө. Эдгээр жагсаалт нь Supabase-аас ирж байгаа бодит өгөгдөл юм.»

## 1:45–2:35 · Түүх, багш, арга хэмжээ

**Үйлдэл:** Түүхийн timeline → багшийн `+` товч → арга хэмжээний дэлгэрэнгүй/цомог.

**Ярих:**

«Түүхийн хэсэг нь хөтөлбөрийн эхлэл, магадлан итгэмжлэл зэрэг хөгжлийн үе шатыг он дарааллаар харуулдаг. Багш бүрийн нэр, албан тушаал, заадаг хичээл, зураг, товч танилцуулгатай. Мэдээллийг албан ёсны эх сурвалжтай тулгасан бөгөөд хуучин тайлангаас авсан мэдээллийн оныг тодорхой тэмдэглэсэн.

Арга хэмжээний хэсэгт нэр, огноо, тайлбар, зурагт цомог байна. Оюутны бүтээгчийн картаас тухайн хүний бүтээл рүү орж болдог. Ингэснээр музейн түүх, хүмүүс, бүтээл хоорондоо холбогдоно.»

## 2:35–3:45 · Оюутны урсгал

**Үйлдэл:** Оюутны account-аар нэвтэрнэ → профайлын танилцуулгыг шинэчилнэ → `Бүтээл нэмэх` → нэр, тайлбар, ангилал, он, технологи, зураг бөглөнө → илгээнэ → `ХЯНАЛТАД` төлөвийг харуулна.

**Ярих:**

«Нэвтэрсэн оюутан өөрийн нэр, профайл зураг, танилцуулгыг шинэчилж, бүтээлээ удирдана. Шинэ бүтээлийн нэр, тайлбар, он зэрэг үндсэн мэдээллийг бөглөж, JPG, PNG эсвэл WebP зураг сонгож болно. Зургийн хэмжээ 8 MB-аас хэтрэхгүй байх шалгалттай.

Илгээсэн бүтээл шууд нийтэд гарахгүй, pending буюу хяналтад орно. Зураг нь Storage-д, бүтээлийн мэдээлэл нь өгөгдлийн санд хадгалагдана. Оюутан өөрийн бүтээлийг засах, устгах боломжтой. Нийтлэгдсэн бүтээлээ засвал дахин хяналтад ордог тул админаар хянагдаагүй өөрчлөлт нийтэд шууд харагдахгүй.»

## 3:45–4:45 · Админ ба өгөгдлийн хамгаалалт

**Үйлдэл:** Админы browser profile руу шилжинэ → Удирдлага → шинээр ирсэн бүтээлийг нээнэ → нийтэлнэ → оюутны browser-оос refresh хийнэ. [ERD](erd.svg)-г нээнэ.

**Ярих:**

«Админ нь бүтээл, багш, арга хэмжээ, цомгийн мэдээллийг удирдаж, оюутны бүтээлийг нийтлэх эсвэл татгалзах боломжтой. Одоо хяналтад байсан бүтээлийг нийтэлсний дараа зочны үзэсгэлэнд гарч байна.

ERD дээр profiles нь Auth хэрэглэгчтэй нэгээс-нэг, exhibits-тэй нэгээс-олон холбоотой. Үзмэр category_id-аар ангилалтай, event_photos нь event_id-аар арга хэмжээтэй холбогдоно. Primary key нь мөрийг ялгаж, foreign key нь холбоосын бүрэн бүтэн байдлыг хангана.

Эрхийг зөвхөн товч нууж хамгаалаагүй. RLS нь database дээр ажиллаж, бусдын бүтээлийг өөрчлөх болон өөрийгөө админ болгох хүсэлтийг хаадаг. Frontend-д service role түлхүүр ашиглаагүй.»

## 4:45–5:45 · Бүтээлч шийдэл: Digital Time Capsule

**Үйлдэл:** `Захиа үлдээх` → богино захиа илгээнэ → админаар захиаг нийтэлнэ → зочны browser дээр хананд гарсныг харуулна.

**Ярих:**

«Миний сонгосон бүтээлч шийдэл бол Digital Time Capsule. Өнөөдрийн оюутан ирээдүйн оюутанд туршлага, зөвлөгөө, дурсамж үлдээнэ. Жишээлбэл “Анхны төслөө жижиг алхмаас эхлүүлээрэй” гэсэн захиа үлдээж болно.

Захиа өгөгдлийн санд хадгалагдах боловч шууд нийтэд харагдахгүй. Админ хянаад зөвшөөрсний дараа захианы хананд гарна. Музей нь зөвхөн өнгөрсөн бүтээлийн архив биш, үе үеийн оюутнуудын бодол, туршлагыг дамжуулах орон зай болж байгаа нь энэ шийдлийн үнэ цэнэ юм.»

## 5:45–6:30 · Responsive, шалгалт, дүгнэлт

**Үйлдэл:** Browser-ийн mobile хэмжээг харуулна → [GitHub](https://github.com/nandydn555-cell/swe-hw), README, тестийн тайланг заана.

**Ярих:**

«Сайтыг компьютер, tablet, утасны дэлгэцэд зохицуулсан. 360, 390, 768, 1440 пикселийн өргөнд халилтгүй байгааг шалгасан. Unit тест, browser-ийн CRUD регрессийн тест болон database-ийн RLS тестээр гол урсгалуудыг шалгасан. Нийтийн сайт дээр бодит Supabase хүсэлтүүд амжилттай ирж, зурагт цомог ачаалж байгааг тусад нь баталгаажуулсан.

GitHub repository-д эх код, commit түүх, суулгах README, ERD, wireframe болон шалгалтын тайлан бий. AI хэрэгсэл ашигласан бөгөөд өөрийн шийдлийн өгөгдлийн урсгал, эрхийн дүрэм, компонентын төлөв ба үйлдлийг код дээр тайлбарлаж чадна. Анхаарал тавьсанд баярлалаа.»

## Demo-ийн өмнөх бэлтгэл

- Оюутан, админы account-уудаа тусдаа browser profile-д нэвтрүүлнэ.
- Бүтээлийн нэр, тайлбар болон жижиг зургийг урьдчилан бэлдэнэ.
- Нийтийн domain дээр зураг upload, захиа илгээх болон нийтлэх урсгалыг нэг удаа давтаж үзнэ.
- Live demo удааширвал тухайн боломжийн код болон шалгалтын тайланг үзүүлнэ. Гүйцэтгээгүй үйлдлийг амжилттай болсон гэж тайлбарлахгүй.
- Нэг удаа хугацаа барьж давтаад, 5–7 минутад багтаана.
